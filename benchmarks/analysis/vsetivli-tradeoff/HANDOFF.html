XReviveVec Handoff

Picking the work up on an x86-64 Linux box. Supersedes the previous handoff: the width design has changed back to vtype, and the measurements it quoted no longer apply.

27 Aug 2026 · three repos, all dirty, nothing committed

The extension takes a wide instruction's width from vtype again, set by vsetivli, in one custom-2 instruction set. The linker recovers the width by interprocedural dataflow. Two real miscompiles were found and fixed on the way; one remains. Performance has never been measured — that is the main reason to be on Linux.

2 · ChangedWhat is different from the last handoff

LLVM

  • Width comes from vtype again. One revive.wadd covers 128/256/512/1024; vsetivli selects. Everything is in custom-2, so custom-1 and custom-3 stay free — which was the whole point of going back.
  • Three things kept from the funct7 work, because they are orthogonal to how width is carried: register moves that name their own count (revive.wmv1r/2r/4r/8r) — a copy is expanded after the vsetvli pass and so can never read vtype; the RVV-avoidance fixes; and spills through revive.wld/wst rather than vs2r.v/vl2r.v.
  • The machine outliner is barred from lifting vtype-dependent code (getOutliningTypeImpl). Without this, 43% of wide instructions end up in OUTLINED_FUNCTION_* bodies whose width is a property of the call site. Behind -riscv-revive-outline-vtype (default: barred).
  • 3016/3016 on CodeGen/RISCV + MC/RISCV.

PolkaVM linker

  • riscv.rs: custom-2 decoder rewritten for the vtype encoding; Inst::SetVtype decodes vsetivli/vsetvli; WideMoveN keeps its own width.
  • BasicInst::Wide.width is now Option<WideWidth>, filled in by a new resolve_wide_widths pass over the basic-block graph. It is interprocedural: a call clobbers vtype, a function's entry is the meet of its call sites, its exit the meet of its returns. It handles the outliner's t0 link register, tail-called outlined bodies, and blocks whose address escapes into data.
  • An unresolvable width is a hard error, never a guess. That is how the remaining miscompile below was found.
  • runblob now enables gas metering and reports gas and steps per export.

3 · BugsTwo fixed, one open

fixed vtype was assumed to survive calls, and nothing restored it

hasCallPreservedVType() returned true for the extension, so a caller reconfigured nothing after a call. The CalleeSavedRegs<(add …, VL, VTYPE)> declaration meant to back that up never took effect, because VTYPE is a reserved register and reserved registers are not spilled as callee-saved. A caller at m2 calling a function that configured m4 resumed at m4: reloads read 64 bytes where 32 were spilled.

Now out of line behind -riscv-revive-call-preserved-vtype, off by default. This is what raised the .text cost of vtype from +17% to +24% against funct7.

fixed Relocated wide accesses did not link

A %lo on revive.wld/revive.wst had no handler — 27 per module in ERC20 alone. Pre-existing and present in both designs, so it was never a regression from the rework; it simply had not been hit. Fixed in both linkers. The %hi half already becomes a full-address LoadAddress, so the access just needs its displacement cleared.

open — wrong code A wide instruction reachable from a call with no configuration

In 3 of 103 modules (XENCrypto variants) a wide instruction sits directly after a call, in the same basic block, with nothing between:

    dc0: jalr    ra                  # call
    dc4: revive.wzext  v8, zero      # runs under whatever the callee left

No other predecessor can supply a configuration, so this is not linker conservatism — it is a miscompile the linker refuses to encode. Fix this first. It is three modules, but it is wrong code rather than a link failure, and it is a class of bug the funct7 design cannot have.

Reproduce:

llc -O2 -mattr=$FEATURES -filetype=obj -o xen.o \
    <ir-intrinsics-oz/XENCrypto/…XENCrypto5001.optimized.ll, features rewritten>
polkatool link --isa revive_v2 -o /dev/null xen.o

Suspicion, unverified: the instruction is a rematerialised wide constant (wzext of zero) placed after RISCVInsertVSETVLI has run. Check what runs between that pass and ExpandPostRAPseudos.

4 · NextWhat to do on Linux, in order

blocker 1. The Linux zygote has no syscall_wide

The generic sandbox implements it (sandbox/generic.rs:759) and the vmctx slot is declared (zygote.rs:70), but the polkavm-zygote crate never mentions it, and sandbox/linux.rs:799 loads a prebuilt binary via include_bytes!. So the recompiler cannot execute a wide instruction on Linux until the zygote implements it and the blob is rebuilt with crates/polkavm-zygote/build-and-replace.sh.

This gates everything else on this list.

the reason to be here 2. Measure the recompiler

Never run. The recompiler needs x86-64 with BMI2 (api.rs:436); the previous host was arm64, so the backend refused to start. Every number so far is interpreter-only.

open 3. Real gas costs for the 32 wide instructions

Until this is done there is no performance measurement at all. runblob sets no cost model, so PolkaVM falls back to CostModel::naive() where every instruction costs one gas — a 256-bit revive.wmul included. The alternative is worse: CostModelKind::Full routes through simulator.rs, which unimplemented!()s every wide instruction and would panic.

So the "gas" column in RESULTS.md is dynamic instruction count. Against the no-extension baseline it flatters the extension badly — one revive.wmul standing in for a ~40-instruction limb chain scores as a 39-instruction saving. Between the three extension arms it is a fair like-for-like count, because they execute the same wide instructions and differ mainly in call overhead.

Note CostModel is at version 3; deserialize rejects any blob of another version, so previously serialised models are refused.

open 4. Six modules never link standalone

They need resolc's own link step rather than polkatool on a lone object — found undefined symbol. Affects every arm equally, so it does not distort the comparison, but it costs six modules of coverage.

open 5. revive is pinned to polkavm 0.35 from crates.io

So resolc cannot emit ReviveV2 itself. The whole measurement pipeline works around this by driving llc over dumped IR and linking with a locally built polkatool. Repointing revive at the local tree would let contracts be built end to end through resolc.

decide 6. Inline arithmetic against the 69-byte instruction budget

VM_COMPILER_MAXIMUM_INSTRUCTION_LENGTH = 69 (zygote.rs:131), pinned near 71 by the static assert at zygote.rs:457 relating sandbox native code size to VM_MAXIMUM_CODE_SIZE. Inline adc/sbb chains do not fit. Raising it means enlarging the sandbox's native code reservation — a memory-layout decision, not a code one.

The object-level penalty does not survive translation. At .text level funct7 looks decisively better; at blob level the gap closes and reverses in total. The vsetivli instructions carry no PolkaVM instruction and the linker drops them, and PolkaVM's own optimiser recovers what the outliner was doing.

The totals hide the distribution Per module, vsetvli-noMO is larger than funct7 on 61 of 94 modules; median +1.58%, mean −0.10%, sum −3.20%. It wins on the big contracts (−3.5%, −4.7%, −6.7% on the three largest) and costs a near-constant ~19 bytes on small ones — one module alone is 24.6% of the total blob bytes. The claim the totals support is that vtype scales better, not that it always wins. If small contracts dominate what ships, funct7 is the better choice and the recommendation flips.

Over the wider 94-module set (dropping the ref column, which excluded 33 modules only because it cannot lower the revive.* intrinsics at all), vsetvli-MO is +12.34% against funct7 on blob size — worse than the 61-module table suggests. Outlining is not worth having: it is bigger, slower to compile, and needs the most linker machinery.

6 · TrapsEach of these cost a cycle

  • Cargo does not track LLVM_SYS_221_PREFIX. After changing LLVM, make install-bin alone leaves resolc linked against the old libraries. Touch a source file first.
  • ninja llc does not rebuild llvm-mc. MC tests passed here while asserting instructions that no longer existed.
  • Most functions carry no target-features attribute — in a typical module 5 of 15 attribute groups do, and the ones doing the i256 work are not among them. Rewriting the attribute alone measures nothing; -mattr is also required. Both harnesses do this.
  • Measure at -Oz. The reference corpus was dumped at -Oz; comparing against -O3 produced an apparent 3.2× regression that was purely the optimisation level.
  • llvm-size needs every .text* section summed, not just .text — objects are function-sectioned, so reading the one section undercounts massively.
  • Gas is only comparable between runs that did the same work. An arm that faults early burns little gas while doing none of the work, which reads as a speed-up. sweep.py matches exports on outcome and host-call count before comparing.
  • Opcode 254 is UNUSED_RAW_OPCODE, a reserved sentinel the ISA asserts must stay free.
  • Instruction groups in the definition macros match positionally. A misordered group silently gives every instruction another shape's signature — there is no name-based safety net.
  • git checkout -- . restores from the index, not from HEAD. With a git revert --no-commit staged, it reinstates the revert and discards unstaged work. Save a patch before switching designs.
